# Incident runbook

First: **what is the user seeing?** Then find the row below. Keep a timeline (time, what you saw, what you did). Nothing here needs a code change to be safe: roll back first, investigate second.

| Symptom                                        | Check                                                                | Action                                                                                                                                                                                                                         |
| ---------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Site down / 502                                | Railway deploy status of `api`; `/health`                            | If the last deploy is bad: redeploy the previous one (`production.md` Rollback). If the logs say `Unsafe production configuration` or `Invalid configuration`: a variable is wrong; fix it (the message names it).             |
| `/ready` is 503                                | The JSON: `database` and `migrations`                                | `unreachable`: the Postgres service; check its status and connection variables. `migrations` applied < expected: a migration did not finish; read the deploy log, fix forward with a new migration, never edit an applied one. |
| Deploy fails at start                          | Deploy log                                                           | A failing migration aborts the deploy and the old version keeps running; leave it, fix forward.                                                                                                                                |
| Users cannot sign in                           | `/api/me` after sign-in; the 403 text                                | Origin mismatch: `BETTER_AUTH_URL` / `APP_BASE_URL` must equal the browser origin exactly. After a secret rotation everyone must sign in again.                                                                                |
| PDF export fails                               | `api` log; `chromium --version` in a shell                           | The image carries Chromium at `/usr/bin/chromium` (`PLAYWRIGHT_CHROMIUM_EXECUTABLE`). Memory pressure kills it: restart `api`.                                                                                                 |
| Insights, alerts or savings stop updating      | `/api/system/jobs`; `worker` log                                     | Worker down: restart it (`restartPolicy` retries 10×). A growing queue with the worker running: look for a failing job repeating in the log. Jobs are idempotent: restarting is safe.                                          |
| Backup state not `ok`                          | `backup.md`                                                          | Fix and take a backup by hand the same day.                                                                                                                                                                                    |
| A design is wrong in the library               | The design's history (audit)                                         | Use the app: retire or supersede; a suspended design stops appearing in exports. Do not edit the database.                                                                                                                     |
| Suspected data corruption or a bad bulk change | Take a backup now, then `restore.md` into a new database and compare | Fix forward through the app; swap databases only for a lost database.                                                                                                                                                          |
| Secret leaked                                  | Which one                                                            | Rotate it (`production.md`); a leaked bucket key: rotate, then review the bucket's access log. A leaked admin password: change it in the app and review the audit log for that user.                                           |

## After every incident

Add a dated note to `docs/progress.md` (what happened, the fix, what would have caught it earlier). If it exposed a gap in a runbook, fix the runbook in the same change.
