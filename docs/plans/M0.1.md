# M0.1 — Repo and tooling

Status: **approved and implemented (2026-10-01).**

## 1. Business objective

Give every later milestone a working, enforced foundation: one monorepo, one command contract, and lint rules that make the safety contract (no hard-coded strings, no physical CSS, validator independence) fail the build instead of relying on review.

## 2. Scope

**In scope**

- pnpm workspace + Turborepo with the layout from `CLAUDE.md`: `apps/api`, `apps/web`, `packages/{engine,validator,rules,db,ui}`, `templates/`.
- TypeScript strict via a shared base `tsconfig`, project references or per-package configs.
- ESLint (flat config, typescript-eslint) with three custom rules (§6), Prettier.
- Vitest in every package, with coverage thresholds (≥ 90% on `engine` and `validator`, enforced once they contain code).
- Playwright with `@axe-core/playwright`; one smoke test against the web shell.
- Every command in the contract, each running and exiting 0 with placeholder content where the real thing arrives later.
- Minimal `apps/api` (Express 5, `/health`, pino) and `apps/web` (Vite + React, one page) so `pnpm dev` and `pnpm e2e` have something real to run.
- `docs/progress.md` first entry; `.gitignore`, `.editorconfig`, `.nvmrc`, CI workflow running the Definition of Done commands.

**Explicitly excluded** (belong to later milestones)

- Any Drizzle schema, migrations, Better Auth, RBAC, audit (M0.2). `pnpm db:migrate` / `db:seed:demo` are stubs that print "not implemented until M0.2/M1.3" and exit 0.
- Tailwind tokens, shadcn, i18n runtime, RTL shell, glossary content (M0.3). M0.1 adds only the lint rules that will police them.
- Seed YAML and rule schema (M0.4); `pnpm test:rules` validates an empty seed directory.
- pg-boss, HiGHS, ECharts, PDF, Railway deploy.
- `pnpm screens` produces a screenshot of the placeholder page only; real quality-gate use starts in M0.3. `pnpm fixtures:export` is a stub (real from M2.2).

## 5. Engineering-correctness risks

M0.1 contains no engineering logic. Risks are about enforcement:

| Risk                                                                       | Mitigation                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Validator quietly imports optimizer code via a re-export or deep path      | Lint rule bans imports resolving to `packages/engine/src/optimizer/**` from `packages/validator`, _and_ a dependency-cruiser-style test (§6) that checks the resolved import graph, since path-pattern lint can be bypassed by barrel files |
| Hard-coded string lint rule has too many false positives and gets disabled | Scope it to JSX text and a defined set of attributes (`title`, `aria-label`, `placeholder`, `alt`) in `apps/web` and `packages/ui` only; allow-list for tests                                                                               |
| Physical-CSS rule misses Tailwind variants                                 | Rule matches class tokens with a regex for `(^                                                                                                                                                                                              | :)-?(m | p)[lr]-`, `(left | right)-`, `text-(left | right)`, `rounded-[lr]`, `border-[lr]`, `float-(left | right)`, and inline `left/right/margin-left…` in style objects; unit-tested with positive and negative cases |
| Coverage gate on empty packages fails or is meaningless                    | Thresholds are configured but only enforced once the package has source files; recorded in progress notes                                                                                                                                   |

## 6. Custom lint rules (the one piece of real logic in M0.1)

1. `khalta/no-hardcoded-ui-strings` — flags literal text in JSX and listed attributes.
2. `khalta/no-physical-css` — flags physical-direction Tailwind classes and inline style properties.
3. `khalta/validator-isolation` — flags any import in `packages/validator` that resolves into the engine optimizer, directly or transitively through `packages/engine` barrel exports.

Implemented as a local ESLint plugin in `tools/eslint-plugin-khalta/`, each with `RuleTester` unit tests including bypass attempts. Written inside the repo (no new dependency); this is domain-specific policy, so custom code is justified under the reuse rule.

## 8. Command contract — what each does in M0.1

| Command                                                        | M0.1 behaviour                                                                                                                                                                  |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm dev`                                                     | Turborepo runs API (tsx watch) and Vite dev server                                                                                                                              |
| `pnpm typecheck`                                               | `tsc --noEmit` per package via Turborepo                                                                                                                                        |
| `pnpm lint`                                                    | ESLint + `prettier --check`                                                                                                                                                     |
| `pnpm test`                                                    | Vitest per package; includes the lint-rule tests and a sample test per package                                                                                                  |
| `pnpm test:rules`                                              | Runs `packages/rules` test script; validates seed dir (empty) against a stub schema                                                                                             |
| `pnpm e2e`                                                     | Playwright smoke + axe on the placeholder page                                                                                                                                  |
| `pnpm screens`                                                 | Playwright captures AR/EN × 1440/1024/390 of the placeholder into `docs/screens/M0.1/` (language toggle is a no-op until M0.3, so AR/EN images are identical and noted as such) |
| `pnpm db:migrate`, `pnpm db:seed:demo`, `pnpm fixtures:export` | Stubs, exit 0 with a clear message                                                                                                                                              |

## 9. Verification strategy

- Run `pnpm typecheck && pnpm lint && pnpm test && pnpm test:rules && pnpm e2e` locally and in CI; all green.
- Lint-rule `RuleTester` suites with positive, negative and bypass cases; a deliberate-violation fixture per rule proves `pnpm lint` fails (checked in a test, not left in the tree).
- Verification note (required for engineering milestones, included for completeness): tests prove the tooling enforces the three policies; they say nothing about concrete engineering.
