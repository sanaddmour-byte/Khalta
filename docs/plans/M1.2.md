# M1.2 — Price matrix

Status: **draft, awaiting approval.** No application code is written until this plan is approved.

Features in scope (`06-features.md`): **F-008** Price matrix per plant, supplier and date, with history and Excel import. Spec refs: `01-domain.md` §2.3 (prices), §8 (price-change trigger, stale prices), §10 (RBAC rows "View supplier prices", "Edit prices", "Export prices or costs"), §14.2 (snapshots); `03-ui.md` screen G; `04-phases.md` M1.2 (gate: paste 20 × 200 from Excel in < 2 s; history never overwritten; approve the grid ADR).

## 1. Business objective

Give procurement one place to keep what each material **costs delivered to each plant**, with every change remembered, so that later milestones can cost a mix at a plant on a named date and prove that a saving is not just a price movement. Procurement should be able to paste a supplier's price list from Excel, see at a glance which prices are stale or missing, and never lose an old price.

## 2. Scope

**In scope**

1. **Price records** (`material_prices`): material, plant, supplier, price (`numeric(12,3)`), unit (`JOD/ton`, `JOD/m3`, `JOD/kg`, `JOD/L`), `includes_delivery`, `effective_from`, `effective_to`, entered by/at, optional note. **One active price per (material, plant, supplier)**: entering a new price closes the previous one the day before; rows are **never updated or deleted** (database trigger), corrections are new rows with a reason.
2. **Price normalization** (pure, `packages/engine`): any unit → **JOD per kg delivered to the plant**. `JOD/ton` ÷ 1000; `JOD/m3` and `JOD/L` need a density/SG (the material's current test: SG for liquids and aggregates by SSD bulk basis is **not** assumed; if the needed property is absent the price is "not convertible" with the missing property named, never defaulted). `includes_delivery = false` adds the plant's haul cost only if QC enables it (see Q5); otherwise the price is flagged "excludes delivery" and cost uses it as entered. All arithmetic in decimal (no floats for money).
3. **Price lookup** (pure): `priceAt(material, plant, date)` returns the single applicable price (supplier chosen by an explicit preferred-supplier flag, see Q4) or "unavailable at this plant". No price = unavailable there, never zero.
4. **Price snapshots** (`price_snapshots` + lines): immutable, named, full copy of the effective prices of the chosen plants at a date. Created on demand now (Snapshot button) and used by baselines in M2.2. Snapshot rows are append-only (trigger).
5. **Price Matrix screen (G)**: materials × plants for one supplier-agnostic "current price" view with a supplier selector per cell group; sticky first column, inline edit, **range paste from Excel**, undo/redo within the session, keyboard navigation, Arabic names first, units on every number, optional heatmap against the cross-plant median, **stale cells hatched with an age badge**, per-cell **history popover with sparkline**, bulk % change, copy column to another plant, effective-date picker, "reason" field for corrections.
6. **Excel / CSV import and export**: `.xlsx` (exceljs) and `.csv` (papaparse). Import is a **preview-then-commit** flow like the rules import: every row validated (known material and plant by code or name, numeric, unit, date), nothing is written until the whole file is clean; unchanged rows are skipped; export logged (RBAC "Export prices or costs").
7. **Stale prices**: a price is stale when older than the tenant setting `stalePriceDays` (null today = "not configured": nothing is ever called stale or fresh, shown as "limit not set"). Stale/missing counts are returned by the API for the dashboard (M5.1 will push them).
8. **Cost visibility**: viewing prices needs `price.view` (Admin, QC Manager, QC Engineer, Procurement, Plant Manager for own plants); editing needs `price.edit` (Admin, Procurement). Cost-visible roles only; Sales never see prices (existing matrix). Plant-scoped roles see only their plants' prices; others 404.
9. **Setup checklist hook**: Materials page shows "priced at N of M plants" using the new data (small, read-only).
10. **ADR 0005 — spreadsheet grid** (required by `CLAUDE.md`): compares ≤ 3 options and records the decision (see §4).

**Explicitly excluded**

- Costing a mix, delivered-cost optimization, baselines and the savings ledger (M2.2, M3.1, M5.1); only the normalization and lookup functions they will call.
- Price-change triggers, debounced re-optimization and "affects N approved designs" (M5.1); the screen shows no such banner yet.
- Supplier contracts, volume tiers, taxes, currency other than JOD, multi-line freight models.
- Demo data generator (M1.3); dev seed gets a few SYNTHETIC prices.
- Approval/four-eyes for price changes (the matrix has no row for it; every change is audited and reversible by a new row).

## 3. Assumptions

- Money is stored as `numeric(12,3)` JOD and handled as **decimal strings** end to end (no JS floats); normalization uses a small decimal helper in `packages/engine` (integer micro-units / `bigint`), tested against hand-computed values.
- Effective dating is by **calendar date in Asia/Amman**; `effective_from` may be in the past (back-dated entry allowed to `price.edit` roles with a mandatory reason) but not earlier than the previous row's start; **no overlapping periods** for the same (material, plant, supplier) — enforced by an exclusion constraint, not just code.
- Unit meaning: `JOD/ton` = metric ton (1000 kg). `JOD/m3` for ready-bulk materials needs a bulk density that does not exist as a tested property in M1.1 (only dry-rodded unit weight for aggregates), so `JOD/m3` is **accepted and stored** but **not convertible** until QC provides the density basis; the matrix shows "needs density" instead of a per-kg value. `JOD/L` converts through admixture SG (test) only.
- Libraries: exceljs and papaparse (approved in §9) and TanStack Table + Virtual (approved) are used; **no new library** unless the ADR chooses option B or C.
- The matrix works on the plants the user can see; the global plant switcher filters columns, "All plants" shows up to 20 columns.
- Performance gate (from `04-phases.md`): pasting 20 plants × 200 materials = 4,000 cells commits in < 2 s end to end on the test database; measured by a test and recorded.

## 5. Engineering-correctness risks

| Risk                                                                       | Mitigation                                                                                                                                                                                                                             |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Wrong unit conversion silently mis-costs every mix                         | Pure `toJodPerKg` with exact decimal arithmetic and fixed-point tests per unit; `JOD/m3` and `JOD/L` return a named "not convertible: missing density" result instead of a guess; property tests (monotonic in price, scale-invariant) |
| Overwriting or deleting a price loses history                              | `material_prices` is append-only (update/delete trigger); the only in-place change allowed is closing `effective_to` of the previous row, done in the same transaction (same pattern as rule versions)                                 |
| Two prices valid on the same day                                           | Exclusion constraint on (material, plant, supplier, daterange); API tests for adjacent, overlapping and back-dated entries                                                                                                             |
| A missing price read as zero                                               | `priceAt` returns "unavailable"; UI shows "no price", not 0; API/engine types make `null` unrepresentable as a number                                                                                                                  |
| Float money errors                                                         | Decimal strings in API and DB, decimal helper for arithmetic, lint-free tests comparing exact strings                                                                                                                                  |
| Stale price treated as current                                             | Stale computed from entry/effective date vs the setting; unset limit is shown as "not configured", never "fresh" (same rule as test freshness)                                                                                         |
| A snapshot mutates later                                                   | Snapshot header and lines are append-only (trigger); lines copy values (not references); hash of the contents stored and re-verified                                                                                                   |
| Excel import corrupts prices (comma decimals, Arabic digits, wrong column) | Preview shows every parsed row with what changes; decimal commas and Arabic-Indic digits normalized with stated assumptions; all-or-nothing commit; stale-preview check (as rules import)                                              |
| Paste of 4,000 cells is slow or half-applied                               | One transaction, one bulk insert; budget < 2 s tested; failure leaves nothing applied                                                                                                                                                  |
| Price visibility leak (Sales, other plants)                                | `price.view` plus plant scoping in the data layer; tests for every role × route, 404 not 403 for other plants; export requires `export.priceCost` and is audited                                                                       |
| Heatmap/colour used as the only signal                                     | Stale = hatch **and** age badge text; heatmap also shows the delta as text on focus; contrast tests                                                                                                                                    |
| Grid inaccessible to keyboard / screen reader                              | ARIA grid roles, roving tabindex, documented key map, axe on the matrix, keyboard e2e (arrows, Enter, Esc, Tab, Ctrl+Z, paste)                                                                                                         |
| RTL breaks column order or arrow keys                                      | Logical CSS only; arrow-key meaning follows `dir`; e2e in Arabic; numbers/units in LTR islands                                                                                                                                         |

## 6. Schema / API / UI impact

- **Schema (migration 0006+):** `material_prices` (as in §2.3 plus `reason`, `created_at`; exclusion constraint on non-overlapping periods; append-only trigger except closing `effective_to`), `price_snapshots` and `price_snapshot_lines` (append-only), `price_import_batches` (preview rows immutable, like `rule_import_batches`); suppliers gain `is_preferred` per (material, plant) via a small `material_plant_suppliers` link (see Q4). Tenant settings unchanged (`stalePriceDays` exists).
- **API:** `GET /api/prices` (matrix, filters), `GET /api/prices/history` (one cell), `POST /api/prices` (single/bulk set with effective date and reason), `POST /api/prices/bulk-change` (% change preview + apply), `POST /api/prices/copy`, import preview/commit, `GET /api/prices/export` (xlsx/csv, audited), `POST /api/price-snapshots`, `GET /api/price-snapshots[/:id]`. Every mutation audited and plant-scoped; read-only POSTs declared as such.
- **Engine (pure):** decimal money helper, `toJodPerKg`, `priceAt`, stale computation, matrix model (cells, selection, paste parsing, undo stack), import row validation.
- **UI:** the Prices screen (nav "Prices" becomes real), history popover with sparkline, import dialog, snapshot dialog, bulk-change dialog; Materials list gains "priced at N/M plants"; `docs/adr/0005-spreadsheet-grid.md`.
- **RBAC:** reuses `price.view`, `price.edit`, `export.priceCost`; no new capabilities.

## 7. Verification strategy

- Definition of Done commands green; zero serious axe violations; `pnpm screens` AR/EN × 1440/1024/390 reviewed against `03-ui.md` §8 (units on every number, stale hatch + text, no price shown as zero, RTL column order and arrow keys).
- **Engine tests:** decimal arithmetic and `toJodPerKg` per unit and per "not convertible" case, `priceAt` at period boundaries, stale with and without a limit, paste parser (Excel block, Arabic digits, decimal commas, ragged rows), matrix model commands and undo/redo, import validation; property tests (conversion scale-invariance and monotonicity, no overlap after any sequence of sets).
- **API tests (real Postgres):** set/close/back-date flows, overlap rejection, append-only at the database level, history order, bulk % change and copy (preview equals apply), import preview/commit all-or-nothing and stale-preview check, snapshot immutability and hash, RBAC matrix extension (every role × route), plant scoping (404), export audit, tenant isolation, **performance: 4,000-cell paste < 2 s**.
- **E2E:** edit a cell inline, paste a block from the clipboard, undo, keyboard navigation in EN and AR, stale hatch/badge, history popover, import preview with an error then a clean file, export, snapshot; plant-manager sees only own plant; Sales has no Prices nav.
- **Verification note** (in `docs/progress.md`): tests prove storage, history, conversion and workflow as implemented. They do **not** prove the prices are right, that delivered-vs-ex-works is interpreted as your suppliers intend, or that the stale-price limit is the right policy.

## 8. Rollback / migration
