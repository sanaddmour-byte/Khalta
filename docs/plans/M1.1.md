# M1.1 — Materials and tests

Status: **approved and implemented (2026-10-01).**

Features in scope (`06-features.md`): **F-005** Plants (up to 20, configurable), **F-006** Materials library with Jordanian market names, **F-007** Material characteristics entry (lab / datasheet / declared, quick entry, paste gradation, ad-hoc materials). Spec refs: `01-domain.md` §2.1–2.3, §2.8; `07-characteristics.md` §2; `03-ui.md` screen J.

## 1. Business objective

Put the plant's real materials into the system, with the lab properties the evaluator and optimizer will rely on, and make it impossible to forget **where a number came from or how old it is**. A QC engineer should be able to type a material's characteristics from a lab report, a supplier datasheet or their own knowledge, see immediately whether the set is enough to evaluate or to design, and see which values are stale, drifting or merely declared.

## 2. Scope

**In scope**

1. **Plants screen** (the API exists from M0.2): list, create, edit, soft-delete, ambient profile, haul cost, plant limit; **Suppliers** (CRUD, bilingual names, contact).
2. **Materials**: categories (`cement`, `scm`, `fine_agg`, `coarse_agg`, `water`, `admixture`, `fiber`, `pigment`), Arabic and English market names (the six Jordanian aggregate labels pre-listed as suggestions, never as size rules), technical name, supplier, source (quarry/plant of origin), standard reference, optional home plant, active flag, soft delete.
3. **Material tests** (versioned lab data) per category with typed, validated properties: aggregates (sieve analysis on a configurable sieve set, SSD specific gravity, absorption, dry-rodded unit weight, latest total moisture, % finer than 75 µm, chlorides, sulfates, optional LA abrasion, flakiness/elongation, shape/texture), cement and SCM (SG, 28-day mortar strength, `c3a_pct`, `pozzolan_pct`, `limestone_pct`, alkali, optional Blaine), admixtures (ASTM C494 type, SG, solids %, min/max dosage, a dosage → water-reduction table with ≥ 3 points, set-retardation effect, water-content convention). Fields: `tested_at`, `lab`, `is_current`, `valid_until`.
4. **Characteristic entry with provenance (07 §2):** each test records `source` = `lab_report` | `supplier_datasheet` | `user_declared`, `declared_by/at`, reason, attachment. Quick-entry drawer with the minimum set highlighted (evaluate vs design), units on every field, **paste a gradation row or a full sieve table from Excel**, live **fineness modulus**, hard validation (passing non-increasing toward finer sieves, 100% at the largest sieve, 0–100) and warn-only sanity ranges. "Upgrade the source later": attaching a report to a declared value creates a new version, history keeps both.
5. **Readiness**: for any material, a list of named blockers for _evaluate_ and for _design_ (07 §2.2), and the evidence status it will carry: `INPUT_MISSING`, `INPUT_USER_DECLARED`, `INPUT_STALE`. The three evidence statuses added by Addendum A1 are added to the shared chip set.
6. **Freshness and drift** (pure functions, shared with the evaluator later): test-age status per category from the QC limit seeds; **drift detection** between consecutive tests of the same material (SG, absorption, FM, fines, C₃A, …) reported as a delta and, when a tolerance is configured, as within / beyond tolerance.
7. **Ad-hoc materials** (07 §2.4): the validated schema and the **promotion** endpoint (ad-hoc definition → library material + `user_declared` test), so the Studio can use them in M3. Storing an ad-hoc material inside a request snapshot waits for requests (M2.1/M3.2).
8. **Materials screen (J)**: list with freshness and source chips, material detail with test history, **gradation chart** (ECharts, log-scale sieve axis never mirrored in Arabic), SG / absorption / FM trend sparklines, drift warnings, admixture dosage-response editor, attachment viewer. Tablet-friendly lab entry (large numeric controls, previous-value context, validation ranges, **offline-safe local drafts**).
9. **Settings screen**: tenant settings form (new: material sanity ranges, `approval_requires_lab_source`) and a **Users** tab (create, role, plant assignment, deactivate, admin password reset) so the first admin can actually run the system. Both use existing M0.2 APIs plus one small settings extension.
10. **Attachments**: lab reports and datasheets stored in PostgreSQL (hash, type, size, uploader), authorized download.
11. RBAC: new capabilities `materials.read`, `materials.write`, `suppliers.write` (see Q3); synthetic **dev data** for screens, labelled SYNTHETIC.

**Explicitly excluded**

- Prices, price snapshots and the grid (M1.2); the full demo dataset (M1.3); legacy import (M1.3).
- Blend/combined gradation, Shilstone factors and any use of the properties in design (M2.1/M3.1). The gradation chart shows individual curves; a grading **envelope** appears only if limits exist (ASTM C33 limits are not on file, so none yet).
- Moisture conversion and the admixture solution-water convention logic (M4.2); M1.1 only stores the convention field.
- Storing ad-hoc materials in requests, the Studio characteristics panel and the DoF meter (M3.2).
- Approval policy for declared values (M4.1); M1.1 only records the data it needs.
- Notifications, insights and expiry nudges (M5.1); freshness is computed and shown, not pushed.

## 3. Assumptions

- Properties use **SI units** and are stored as validated JSON per category (a Zod schema per category is the single source for API, forms and DB checks); sieve sizes are numeric **millimetres** internally. Entry accepts the common US labels (No. 4, 3/8 in, …) through a fixed lookup and shows both.
- **Fineness modulus** is computed, never typed: Σ cumulative % retained on the standard series ÷ 100. The series is an engineering parameter seed (`eng.fm.sieves`, starter = the ASTM C125/C136 series; unverified, QC confirms). If a needed sieve is missing, FM is "not computable" with the missing sieves named.
- Specific gravity and absorption are on the **SSD basis** (the design basis); the form says so on the field. Entering an oven-dry SG is out of scope.
- Test-age limits (`eng.test_age_limit_days.*`) and drift tolerances are **null until QC sets them** (no invented numbers). With a null limit a test never becomes "expired" and the UI says "limit not configured"; with a null tolerance, drift shows the raw delta only.
- Sanity ranges default to the examples in `07 §2.3` (aggregate SG 2.3–3.1, absorption 0–6 %) as **warn-only tenant settings**.
- Library additions (approved list): Apache ECharts (`echarts`, `echarts-for-react`). No ADR needed. Playwright already covers E2E.
- Materials are tenant-level with an optional **home plant**; plant-scoped roles see materials of their plants plus shared ones; prices (M1.2) decide availability per plant.

## 5. Engineering-correctness risks

| Risk                                                              | Mitigation                                                                                                                                                                                                                       |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A wrong FM or a mis-keyed sieve silently corrupts later designs   | FM from one pure function with fixed-point examples (hand-computed sands), property tests (monotonic in coarseness; unchanged by sieves above the 100% line); hard validation of the gradation shape on entry **and** at the API |
| Percent **passing** vs **retained**, or oven-dry vs SSD, confused | Field labels carry the basis and unit; paste parser states what it assumed and shows the parsed table before saving; SSD-only                                                                                                    |
| Typed ("declared") numbers treated as lab data                    | `source` is mandatory; `INPUT_USER_DECLARED` propagates to readiness; `lab_report` requires an attachment; changing a value after the fact creates a new version, never an edit                                                  |
| Stale tests used silently                                         | Freshness is computed from the seed limit; absent limit is shown as "not configured", never as "fresh"                                                                                                                           |
| Drift misreported (spurious alert or missed change)               | Detection compares consecutive versions of the same material only; unit-tested with injected tolerances at, below and above the boundary                                                                                         |
| Material source change disguised as a new test                    | A material has a fixed `source`; changing it prompts "new material"; drift compares only within one material                                                                                                                     |
| Two "current" tests for one material                              | Partial unique index on current version; supersede in one transaction (same pattern as rules)                                                                                                                                    |
| Insecure file upload                                              | Allow-list of types checked by content signature, 10 MB cap, hash stored, download only through an authorized endpoint with `Content-Disposition: attachment`, never served from a public path                                   |
| Plant scoping bypass for materials and tests                      | Scoping in the data layer; tests request another plant's material and test as each scoped role; 404 not 403                                                                                                                      |
| Offline drafts leaking after sign-out                             | Drafts live in browser storage keyed by user id and are cleared on sign-out; they never contain attachments                                                                                                                      |
| Evidence chips used as scores                                     | Closed type set (now 12 values); tests that no numeric prop exists                                                                                                                                                               |

## 6. Schema / API / UI impact

- **Schema (migration 0004+):** `suppliers` (existing, gains contact fields as needed), `materials`, `material_tests` (versioned, `is_current`, `source`, `attachment_id`, `properties jsonb`, `valid_until`), `attachments`; triggers: no hard delete, test content immutable (new version instead), at most one current test per material. Tenant settings schema gains sanity ranges and `approvalRequiresLabSource`.
- **API:** `/api/suppliers`, `/api/materials` (list/detail/create/patch/soft-delete), `/api/materials/:id/tests` (create new version, list history), `/api/materials/:id/readiness`, `/api/materials/promote`, `/api/attachments` (upload, download), settings extension. All mutations audited, tenant-scoped, RBAC-gated.
- **Engine (`packages/engine`, pure):** `fineness-modulus`, gradation validation and paste parsing helpers, per-category property schemas, minimum sets, freshness, drift.
- **UI:** Plants, Materials (list, detail, quick-entry drawer, charts), Settings (+Users) screens; nav "Materials", "Plants", "Settings" become real; chips for the three new evidence statuses.
- **RBAC:** three capabilities added to the matrix and the generated tests.

## 7. Verification strategy

- Definition of Done commands green; zero serious axe violations; `pnpm screens` AR/EN × 1440/1024/390 reviewed against `03-ui.md` §8 (including: every number has units; every value shows its origin; declared values visibly labelled).
- **Engine tests:** FM on hand-computed sands and coarse aggregates, non-computable cases, gradation validation (every rejection reason), paste parser (Excel row, full table, Arabic-Indic digits, decimal commas, malformed input), minimum sets for every category and workflow, freshness with and without limits, drift at/below/above tolerance and with null tolerance, property tests (FM and validation invariants).
- **API tests (real Postgres):** CRUD and RBAC matrix extension, plant scoping, versioning (`is_current` flips atomically; history kept), source rules (`lab_report` needs an attachment; declared flagged), minimum-set blockers, sanity warnings vs hard errors, attachment type/size/hash and authorization, promotion of an ad-hoc material, audit rows, tenant isolation.
- **E2E:** create a supplier and material, enter a test through quick entry with a pasted gradation (live FM, rejection of non-monotonic data), attach a report, see freshness/drift/declared chips, the "Generate lists gradation as a blocker" case from F-007's criteria, EN/AR + RTL, tablet width, offline draft restore.
- **Verification note** (in `docs/progress.md`): tests prove calculations, validation and workflow as implemented. They do **not** prove the FM series, sanity ranges, test-age limits or drift tolerances are the right engineering policy, nor that entered lab values are true.
