# Gap map — audit of 2026-10-04

Method: read the code, schema, tests and ADRs for each area of the improvement request. "Exists" means found in code _and_ covered by a test. Nothing here was assumed from the specs.

## Resolution

The gaps below were worked through in phases 2 to 6 of the same programme. Read the tables as **the state at the audit**; the current state, with evidence, is in `docs/readiness-matrix.md`. In short: the lifecycle policy, project requirements, batch preparation with the v2 export, optimizer transparency, strength-model and trial governance, change-impact workflows, role dashboards, alert ownership, savings attribution and the cement classification were built and tested; the Dashboard is no longer a placeholder. Not closed: manual accessibility review, dedicated phone workflows, the Arabic review, and everything that needs an engineering value or a live service.

Legend: ✅ exists · 🟡 partial · ❌ missing.
