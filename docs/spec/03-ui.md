# UI/UX specification

## 1. Users and devices

| Persona | Context | Primary jobs | Device |
|---|---|---|---|
| QC Manager | HQ office | Verify rules, attest legacy designs, approve, review insights and savings | Desktop, wide screen |
| QC Engineer | Plant lab / site office | Evaluate and iterate designs; enter tests, trial batches, strength results | Laptop / tablet |
| Procurement | Office | Maintain the price matrix | Desktop |
| Plant Manager | Plant | Designs in production, alerts, test entry, release/suspend (own plant) | Tablet / phone |
| Sales Engineer | On the road | Approved designs and PDFs for clients and consultants | Phone (read-only) |

Desktop-first for the Design Studio and Price Matrix; fully usable on tablet; read-only mobile for the Library, design cards, PDFs and insights.

## 2. UX principles

1. **Progressive engineering workflow.** The Studio has two clearly labelled entry paths — **Evaluate existing mix** and **Generate trial recommendation** — and four explicit stages: Requirements → Candidates → Inspect & Validate → Save / Request Trial. Desktop may keep adjacent stages visible as panes, but the current stage is always obvious. Re-solving is debounced and cancellable.
2. **Explain every number.** Clicking any computed value opens a popover: formula, inputs, rule and clause, test record, price record, model version.
3. **Evidence, not confidence.** Candidates and designs show evidence-status chips (CLAUDE.md), never a percentage or score.
4. **Show the money honestly.** Cost/m³ and Δ vs best are visible to cost-visible roles; every saving shows its state (theoretical / approved / realized), period and price basis.
5. **Hard limits are not levers.** Code and project limits appear as "binding" diagnostics, never as sliders or "relax to save" actions.
6. **Proactive, not noisy.** Insights go to an inbox; only critical items interrupt.
7. **Plant context is global.** A persistent plant switcher scopes prices, materials and designs.
8. **Undo over confirm** for edits; regulated actions (approve, attest, release, suspend, verify rule) require a typed e-signature note.
9. **Keyboard-first.** `Ctrl/Cmd+K` palette ("C30 S2 عقبة", "evaluate design", "prices AQB-01"); full grid keyboard navigation.
10. **Empty states teach**, e.g. "Add a sieve test for فولية to unlock blend optimization".
11. **Never color alone** — icon + text + color; WCAG 2.2 AA; visible focus rings.
12. **Role-aware** — fields a role cannot see are absent, not blurred.

## 3. Information architecture

Side navigation (start side — right in Arabic): **Dashboard · Design Studio · Mix Library · Insights · Savings · Materials · Prices · Plants · Rules · Imports · Settings**.
Top bar: plant switcher · command palette · language toggle (ع / EN) · notifications · user menu.
First-run **setup checklist**: plants → materials → tests → prices → rules verified → legacy designs attested → engineering parameters → first trial recommendation.

## 4. Key screens

**A. Design Studio** — header shows the entry path (Evaluate / Generate) and the current stage.

- *Requirements:* strength picker (B-grade, EN class or MPa with live conversions); plain-language exposure picker ("Where will this concrete be?" → icon cards → F/S/W/C chips); code mode control (ACI | JS | Both) and PROJECT override drawer; slump, NMAS, pumpable, placement, season, haul time, optional element geometry; material pool as chips grouped by category (Arabic names first), defaulting to materials priced at this plant; "Advanced" for margins and SCM ranges (QC roles). `special` flags show the "manual design required" banner. In Evaluate mode this stage also takes the proportions.
- *Candidates:* ranked cards — cost/m³ in large tabular numerals, Δ vs best, binder, w/cm, a margin bar per governing constraint, code badges, evidence chips, `TRIAL_REQUIRED`; pin up to 4 to compare. When no compliant candidate exists, a diagnostic panel names the binding hard rules ("max w/cm 0.45 — JS S2 — binding") with no saving attached. Guardrail what-ifs ("Shilstone CF 50 → 45: −0.310 JOD/m³, hypothetical") are shown to QC roles only, labelled hypothetical.
- *Inspect & Validate:* tabs Proportions · Compliance · Strength evidence · Gradation · Cost · Traceability · Validator report; what-if sliders limited to prices, slump, safety margin and guardrails; "Compare plants".
- *Save / Request Trial:* "Save as draft", "Request trial" (enabled only after a validator pass), with a summary of evidence gaps.

**B. Proportions table** — Material (AR market name + technical name) | kg/m³ SSD | L/m³ | abs. volume m³ | JOD/kg | JOD/m³ | % of cost (mini-bar). Sticky totals: Σ volume = 1.000 m³ ✓, fresh density, total cost. Toggle SSD ⇄ batch weights with moisture inputs inline and the conversion trace.

**C. Gradation chart** — log-scale sieve axis, never mirrored in Arabic; envelope band, combined curve, toggleable individual aggregates; optional 0.45-power line; out-of-envelope sieves marked with % deviation. Companion Shilstone CF/WF chart with the target box.

**D. Compliance table** — `02-codes.md` §8; failures first; filter by code and class; clause refs link to Rules.

**E. Mix Library** — dense virtualized table with saved views ("My plant – in production", "Trial candidates", "Suspended", "Legacy – awaiting attestation", "Needs revalidation"); per-material kg/m³ column chooser; status chips using the §14.1 states; bulk re-evaluate / export / compare. Mobile: card list with search, status, "Share PDF".

**F. Design Detail** — lifecycle stepper with all §14.1 states and the evidence required for the next gate; transition history; version timeline with side-by-side diff; trial batch log with acceptance results; strength chart (results vs f'c and f'cr, running average of 3, acceptance line); approve/attest/release/suspend with e-signature (approval blocked for the author). A plain-language **"Why this changed"** summary states the economic driver, governing limits, evidence gaps and next required action.

**G. Price Matrix** — spreadsheet feel: materials × plants, sticky first column, inline edit, range paste from Excel, undo; optional heatmap vs cross-plant median; stale cells hatched with age badge; history sparkline popover; bulk % change, copy column, Excel import/export. Saving shows "affects N approved designs — re-evaluation queued for 15 min from now" (from M5.1).

**H. Insights Inbox** — triage view with severity, type, plant, **theoretical** saving (JOD/m³ and JOD/yr, labelled); Accept (creates a prefilled trial-only draft), Dismiss with reason, Snooze.

**I. Savings** — ledger view and KPIs in three separate columns (theoretical / approved / realized) with period, eligible vs actual volume and price snapshot used; drill-down to each entry.

**J. Materials** — test freshness and expiry; test history, gradation chart, SG/absorption/FM trend sparklines, drift warnings; admixture dosage-response editor. Tablet lab entry uses large numeric controls, unit labels, previous-value context, validation ranges and offline-safe drafts.

**K. Rules** — grouped by ruleset → chapter; value, class, clause, verification badge, "used by N designs"; verify action (QC Manager); engineering parameters section; CSV import with validation preview.

**L. Compare Plants** — plant, best cost/m³, Δ vs current, haul estimate, delivered estimate; material-mapping confirmation; all values theoretical.

**M. Imports** — legacy designs and JS rule values: upload → column mapping → fuzzy material matching (Arabic first) → validation preview → commit → evaluation report → attestation queue.

**N. Dashboard** — KPI tiles (average material cost/m³ per plant with trend; savings by state; designs by state; volume covered by evaluated designs; stale prices and expired tests; unverified rules; low-strength alerts), insight highlights, "continue where you left off".

## 5. Visual language

- **Tone:** industrial, calm, precise — an engineering instrument, not a marketing site.
- **Palette — grey, dark green, olive green; red/green for status.** CSS variables on `:root` with a dark-mode override, exposed as Tailwind tokens; no hex values in components.

| Token | Role | Light | Dark |
|---|---|---|---|
| `--grey-50` | App background | #F5F5F4 | #161615 |
| `--grey-100` | Surfaces / cards | #FFFFFF | #1F1F1E |
| `--grey-200` | Borders, dividers | #D9D9D6 | #33332F |
| `--grey-500` | Secondary text, icons | #6B6B67 | #A3A39E |
| `--grey-800` | Headings | #2B2B29 | #E8E8E5 |
| `--grey-900` | Body text | #1A1A19 | #F2F2F0 |
| `--green-dark-700` | Primary: buttons, active nav, selection, links | #1E4D35 | #5FA67E |
| `--green-dark-800` | Primary hover / pressed | #163D2A | #7BBF97 |
| `--green-dark-50` | Primary tint (selected rows) | #EAF3EE | #1B2E24 |
| `--olive-600` | Secondary accent, 2nd chart series, progress | #6B7A2A | #A3B05A |
| `--olive-100` | Olive tint (pinned candidates, chips) | #EEF0DC | #2A2E18 |
| `--pass` | Pass / compliant / savings | #1F8A43 | #4CC273 |
| `--pass-bg` | Pass tint | #E4F5E9 | #163322 |
| `--fail` | Fail / error / cost increase | #C62828 | #EF5350 |
| `--fail-bg` | Fail tint | #FDE8E8 | #3A1B1B |
| `--warn` | Near-limit, stale or unverified evidence | #B7791F | #E0A43A |
| `--warn-bg` | Warning tint | #FFF4DB | #33280F |

- **Usage rules:** about 80% grey, 15% dark green, 5% olive. Red and green are reserved for status. Pass-green is always the brighter `--pass` on `--pass-bg` with a ✓ icon and label — brand dark green is never a status color. Savings use `--pass` with ↓, increases `--fail` with ↑. Code badges: ACI = `--grey-800` outline, JS = `--green-dark-700` fill, PROJECT = `--olive-600` fill. Charts: combined curve `--green-dark-700`, envelope `--grey-200`, aggregates in grey/olive tints, out-of-envelope markers `--fail`. Every text/background pair ≥ 4.5:1.
- **Typography:** IBM Plex Sans Arabic / IBM Plex Sans; IBM Plex Mono for codes like `CEM II/A-P 42.5N`; tabular numerals in numeric cells; Arabic line-height 1.7, Latin 1.5; no letter-spacing or uppercase on Arabic.
- **Density:** comfortable/compact per user; compact default for tables.
- **Motion:** ≤ 150 ms transitions; skeleton loaders, not spinners.

## 6. RTL and bilingual rules

- `dir` on `<html>` with Radix DirectionProvider matching; logical CSS only.
- Mirror directional icons; never mirror charts, sieve axes, numbers or product codes.
- Wrap mixed-direction tokens in `<bdi>` / `dir="ltr"`: units (kg/m³), classes (C30/37), codes (CEM I 42.5N-SR3), clause refs, numbers with units.
- Numeric columns end-aligned with tabular numerals; Western digits by default, Arabic-Indic as a setting.
- Zero hard-coded UI text (ESLint-enforced).

## 7. PDF submittal

Company letterhead and plant details; design code + version + lifecycle state + QR code linking to the live version; AR / EN / bilingual side-by-side; sections: requirements, materials with sources and test dates, proportions (SSD + batch), compliance table with classes, evidence and clause refs, strength evidence, gradation chart, f'cr derivation, approval block (names, dates, e-signatures, or legacy attestation reference); disclaimer; A4 print-tested. Only `approved` or `in_production` designs produce a submittal without a "NOT APPROVED — TRIAL ONLY" watermark.

## 8. UX quality gate (before closing any UI milestone)

1. `/dev/components` shows every `packages/ui` component in LTR and RTL, light and dark.
2. `pnpm screens` captures each new screen in AR + EN × 1440/1024/390 px using the demo dataset (no empty screens).
3. Review screenshots and fix before reporting done:
   - no mirrored numbers, codes or charts;
   - no clipped Arabic text;
   - no physical left/right CSS;
   - visible focus states;
   - empty, loading and error states present;
   - every number has units;
   - cost visible in the Studio for cost-visible roles and absent for others;
   - no hard rule shown as an adjustable lever or with a saving attached;
   - every saving labelled with its state.
4. Axe check in Playwright: zero serious violations.
